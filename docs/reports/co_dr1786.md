# Colorado DR 1786 CSV Export

The `/v1/reports/co/dr1786` endpoint produces the CSV required for monthly
Colorado retail delivery fee filings. Each row represents a single order-level
fee event emitted by the fee engine.

## Columns

| Column | Description |
| --- | --- |
| `Transaction Date` | ISO-8601 calendar date when the order fee was recorded. |
| `Order ID` | Store-scoped identifier for the order that triggered the fee. |
| `Fee Amount` | Fee amount formatted as a currency string (positive for new fees, negative when reversed). |
| `Delivery Method` | Fulfillment channel captured at the time of assessment (`ship`, `pickup`, etc.). |
| `Reason Codes` | Comma-delimited list describing why the fee was assessed or reversed. |

## Sample CSV

The fixture in `backend/tests/fixtures/reports/co_dr1786.csv` is treated as the
golden sample for regression tests. The first rows are shown below:

| Transaction Date | Order ID | Fee Amount | Delivery Method | Reason Codes |
| --- | --- | --- | --- | --- |
| 2024-07-01 | CO-001 | $0.28 | ship | CO_HAS_TAXABLE_ITEM |
| 2024-07-02 | CO-002 | $-0.28 | ship | CO_HAS_TAXABLE_ITEM,REVERSAL_DELIVERY_CANCELLED |

## Reversal handling

Reversals are emitted as follow-up rows with a negative `Fee Amount` so that the
net total matches what should be remitted. The `Reason Codes` column preserves
both the original trigger (`CO_HAS_TAXABLE_ITEM`) and the reversal reason (for
example, `REVERSAL_DELIVERY_CANCELLED`). Consumers should aggregate by order and
sum the `Fee Amount` values to compute their filing totals.
